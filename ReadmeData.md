# Data

Every file in this folder is generated by `scripts/real_data.py` and holds
measured or derived values from real, publicly available sources -- nothing
here is synthetic. Regenerate any of them by re-running that script (see the
top-level README for setup).

| File | Rows | Source | What's in it |
|---|---|---|---|
| `calibration_real.csv` | 127 | `FakeSherbrooke` snapshot, `qiskit-ibm-runtime` | Per-qubit `T1_us`, `T2_us`, `frequency_GHz`, `readout_error`, `sx_gate_error`/`sx_gate_length_ns`, and the neighbour-averaged `mean_ecr_error`/`mean_ecr_length_ns`, for all 127 qubits of the real ibm_sherbrooke processor. |
| `coupling_real.csv` | 144 | Same snapshot | One row per physical ECR-coupled qubit pair (`qubit_a`, `qubit_b`) on the real heavy-hex coupling map, with that pair's `ecr_error` and `ecr_length_ns`. |
| `circuit_benchmarks_real.csv` | 123 | [QASMBench](https://github.com/pnnl/QASMBench) | One row per parsed `.qasm` circuit: `family` (arithmetic, algebraic, search, simulation, variational, entanglement, QEC, ...), `n_qubits`, `depth`, `gate_count`, and the 1-/2-qubit gate split. |
| `transpile_overhead_real.csv` | 11 | QASMBench circuits transpiled with `qiskit.transpile()` | Logical vs. physical depth and 2-qubit gate count after routing one representative circuit per family onto the real ibm_sherbrooke coupling map (`optimization_level=1`, `seed_transpiler=42`). |
| `supermarq_real.csv` | 5 | [SupermarQ](https://github.com/Infleqtion/client-superstaq) feature formulas, computed on QASMBench circuits | The six SupermarQ capability features (communication, liveness, parallelism, measurement, entanglement, critical depth) for the largest tractable circuit in each of six families. |

Note on `sx_gate_length_ns`: on this backend it's a fixed, device-wide pulse
duration with zero variance across all 127 qubits, so it isn't useful as a
per-qubit feature. Anywhere the analysis needs a varying two-qubit-linked
timing feature, `mean_ecr_length_ns` is used instead.

`QASMBench` itself (the raw `.qasm` source files) is not vendored in this
repository -- it's a large third-party benchmark suite with its own license.
Clone it separately and point `scripts/real_data.py` at it via the
`QASMBENCH_DIR` environment variable if you want to regenerate
`circuit_benchmarks_real.csv`, `transpile_overhead_real.csv`, or
`supermarq_real.csv` from scratch.
